# Scandoc Zero harness QA

## Requirements and checks
- Current repository pins: fetch all three remotes; preserve source checkout bytes.
- Sphere event: reference the recorded local initialisation roles; do not assert a fresh upstream ignition or external LLM inference.
- Source fixture: execute current TouchSurfacePair for paired / missing ports / retained normal residue; execute sphere check with positive and negative controls.
- Ignition: six identities and two original Sentinel writer instances; all scripted roles accept.
- Step: sampled metric and velocity decomposition; bounded 64-frame session.
- Negative controls: normal escape and tangent shear violate geometric metric while preserving declared identities; disagreement commits neither chain nor frame.
- Receipt validation: verify chains and A/B cross-reference; independently hash exported entries in Node.
- Reset: clears both chains and frame; geometry scope switches only before ignition.
- Export: browser JSON download; includes synthetic derived values and explicit limitations only.
- Slow playback: pause, fault stop, cap stop; reduced-motion preference disables continuous playback.
- Visual: desktop and phone, light/dark, all key lower regions, no unintended page overflow.

## Deliberate exclusions
No actual model inference, no fresh upstream ignition, no imported private alignment, no live AGI/core, no production integration, no sphere canon, no full VelocitySplat implementation, no credit settlement, no source authentication, no observed world feedback.

## Public page evidence binding

`site/harness/evidence.json` follows `scandoc-zero-page-evidence/1`. It permits only a reviewed status record containing the exact public repository and HTML path, full source revision, HTML SHA-256, artifact build time, successful deployment URL/time/source, firing event time/producer/six named legs/source, and the local-stub flag. Evidence-source URLs must be public HTTPS GitHub/GitHub Pages URLs; each source review must postdate its evidence and be no more than 30 days old. The record contains no raw traces, contact data, credentials or private-source inventory. Absent evidence remains PENDING for firing and UNVERIFIED for deployment; malformed, stale or mismatched records fail closed. The checker currently has no trusted deployment source or firing producer allowlisted, so even structurally complete synthetic records remain UNVERIFIED.

The evidence fields are distinct: `firing.event_at`, `artifact.built_at` and `deployment.succeeded_at` must be separate ordered timestamps. The browser's one-time displayed clock is observation time only and is not part of the evidence record. No real-world firing control, source authentication, signature, attestation or access grant is provided by this preview.

If an authorized firing producer and deployment-completion source become available, a reviewer can prepare a sanitized record for the exact deployed `harness/index.html`: bind its full repository revision and HTML digest, cite the public reviewed producer and deployment evidence, record their actual event/build/deployment timestamps, and list the six explicit leg identifiers only when independently supported. Update the checker’s source allowlists only after those sources are separately reviewed, then run `node tools/build-evidence.cjs` and `node tools/check.cjs` before any publication decision. A timestamp alone is never sufficient. The Pages workflow retains its existing evidence-build and check steps before artifact upload and deployment; it provides no post-deployment completion evidence source today.
